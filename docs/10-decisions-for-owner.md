# Decisions for the owner

> Source: generated from the approved consolidation plan (planning session of 2026-09-03; workflow `wf_8edc6cab-3ac`, 44 agents). The evidence behind every claim is under `knowledge/reviews/`. Legal statements carry one of four labels: PRIMARY, SECONDARY, REPO, UNVERIFIED (see `docs/11`).

Four independent architects designed the product from different lenses (persona/UX, MVP sequencing, domain data model, controls/trust) and three judges scored them. The designs converge on most of the architecture; where they disagree, the choice is yours. Each row gives the options, my recommendation, and why.

**Converged (no decision needed, recorded for the record):** Next.js 15 / React 19 / Drizzle / Postgres as the base, because the hardened, tested code lives there and Precog's app does not build; Precog's engines lift as a pure TypeScript package with demo-data imports replaced by parameters; shared database with `tenant_id` on every table plus Postgres row-level security as the backstop; long-lived containers with a Postgres-backed job queue instead of Vercel serverless; drizzle-kit migrations replacing the hand-rolled DDL array; mandatory MFA with recovery codes; server-side session table with the JWT watermark kept as belt-and-braces; default-deny API wrapper with a CI test over every route; hash-chained append-only audit log plus a PHI read log; notes attached to encounters by a required foreign key; append-only ledger with balances as sums and estimates kept out of it; dual release evaluated server-side inside the posting transaction; no scoreboards, letter grades, or per-person rankings anywhere; published rate card and exit terms; clearinghouse via adapter, never direct payer connectivity; card data via hosted fields only.
