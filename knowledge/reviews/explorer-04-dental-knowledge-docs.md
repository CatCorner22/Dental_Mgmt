## Summary

The `dental` repo carries an unusually mature research-and-doctrine corpus that is almost entirely portable to a full PMS: ~45 knowledge files (`/home/user/catcorner22/dental/knowledge/`), 11 design/architecture docs (`/home/user/catcorner22/dental/docs/`), a 9-file agent skill with clinical reference material (`/home/user/catcorner22/dental/skill/`), and a DTCG design-token export (`/home/user/catcorner22/dental/design-tokens.json`). The corpus is organized around one product thesis — Smile Notes is a *de-identified, deterministic note-standardization layer that sits beside Curve Hero and never holds PHI* — and the single most important fact for the merge is that this thesis is explicitly load-bearing for almost every safety argument in the documents. `/home/user/catcorner22/dental/knowledge/artifact/cornerstone-dental-arts.md` §7 states it plainly: "The tool is de-identified, therefore compliance is straightforward. This premise is doing the heaviest lifting in the whole design." A merged PMS that WILL hold PHI invalidates that premise and must re-derive every control the docs currently get for free.

The research is organized into five strata. (1) **Competitive benchmark**: a deep Curve Hero teardown (`sources/curve-hero-pms-clinical-documentation.md`, `sources/curve-hero-des12-blueprint.md`, `sources/builder-text-blocks-predictive-ux.md`, `benchmarks/smile-notes-vs-curve-hero.md`) covering Sidekick, note tags, Forms two-tier builder, checkout auto-conversion, Care+ ambient AI, voice charting, and the behavioral traps that decide correctness. (2) **Adversarial red-team**: 24 hostile personas with per-lens digests (`sources/adversarial-*.md`, `tn-board-investigator-hate.md`, `carrier-risk-false-confidence-uw.md`), consolidated in `sources/adversarial-hate-panels.md` and resolved into a binding "Honest Finish" contract in `sources/adversarial-hate-codesign.md`. This is the highest-value asset in the repo — it is a pre-written kill-sheet for a commercial PMS. (3) **Tennessee law**: statutes, Board rules, supervision matrices, retention, sedation permits, teledentistry, infection control (`skill/references/tennessee-dental-law-summary.md`, `docs/tn-dental-authority-map.md`, `docs/tn-license-scope-mermaid.md`, `sources/tn-des12-legal-blueprint.md`, `sources/tn-dental-note-standardization-curve-hero.md`, `sources/tn-dental-legal-best-practices.md`). (4) **Design system and brand**: Daylight-chart palette, severity luminance ladder, CVD/dyslexia encoding rules, glove-first target floors (`docs/brand.md`, `docs/design-tokens.md`, `design-tokens.json`, `sources/color-theory-uiux.md`, `sources/adversarial-cvd-dyslexia-hate.md`, `sources/adversarial-a11y-advocate-hate.md`). (5) **AI governance**: a formal model charter with a control ladder, a measured Gate-1 baseline, and hard "no" positions on training (`docs/model-charter.md`, `docs/bytestar-architect-audit.md`, `sources/bespoke-llm-build-paths.md`, `docs/voice-dictation-architecture.md`).

Maturity is high on doctrine and low on live validation. Every research file carries an explicit epistemic frame: the adversarial panels say "None is a live Cornerstone interview, Board contact, carrier underwriting quote, OCR review, or DSO RFP response"; the artifact's §5 says "No statistical analyses performed, and that is worth stating plainly"; the source ingest log rates every source "commissioned consultancy or research report supplied by the project owner, not peer-reviewed primary literature." The most repeated admission across the corpus is that nobody has watched a real appointment: "the place a documentation tool fails is the ninety seconds between patients, and we have no observation of that" (artifact §6). Any PMS built on this material inherits well-argued hypotheses, not measured outcomes.

The corpus also contains an explicit product roadmap in several places, and — critically for the merge — an explicit EDR-agnostic seam. `sources/scope-aware-templates-and-multi-edr.md` documents `src/lib/edr/product.ts` with `EDR_PRODUCT_NAME` / `NEXT_PUBLIC_EDR_PRODUCT_NAME` so Curve Hero is "the default charting product name, not a hard-wired architecture," while explicitly listing "bidirectional PMS integration or write-back" as a non-goal. `docs/GO-LIVE.md` §6 confirms the env-var contract. That seam is the hinge on which the whole codebase can pivot from "companion to a PMS" to "the PMS itself."

## Architecture

**Document architecture and how the knowledge flows.** The corpus uses a deliberate three-layer filing discipline enforced by an `ingest-source` skill: raw sources land in `knowledge/sources/<slug>.md` with a fixed front-matter block (Source, Type, Author/Origin, Published, Ingested, Tags), get exactly one indexed line in `knowledge/INDEX.md`, and are synthesized (never duplicated) into `knowledge/artifact/cornerstone-dental-arts.md` — the "living synthesis" with a progress log, a source-confidence table, key findings, known unknowns, suspected unknown unknowns, structured self-challenges, and ranked next actions. `knowledge/benchmarks/` holds derived assessments (Curve comparison, UX/perf review). `docs/` holds decision records and design system truth. `skill/` holds the clinical reference corpus that is meant to be read by an agent at authoring time. Each file cross-links siblings and, unusually, cites the exact source file path plus the code path it drove — e.g. `sources/tn-des12-legal-blueprint.md` says PC1107 was "implemented as `supervision-2027` in `src/lib/audit/rules/` the day this was ingested."

**Where enforcement happens (the doctrine to carry forward).** The corpus is explicit that enforcement is server-side and deterministic, never client copy. `benchmarks/smile-notes-vs-curve-hero.md`: "a five-severity deterministic audit that blocks export server-side, so a tampered client cannot push a note past the gate." `sources/adversarial-hate-codesign.md` acceptance tests include "Open killers: Copy/File locked; submit API returns 422; no ack checkbox" — i.e. the same gate exists on both the client and the submit route. `skill/references/data-hygiene-guide.md` notes "The same check runs again on the server, so the gauntlet cannot be skipped by calling the API directly." The pattern to inherit: **every gate is a pure helper, unit-tested in isolation, then called from both the UI and the API route.**

**The severity/readiness model** is the spine of the whole product and is documented twice — once as agent instructions in `skill/assets/dental-note-templates.md` §"Severity and readiness", once as tokens in `design-tokens.json`. Five severities: `S0 STOP` (privacy, wrong-record/wrong-site, material contradiction, unsafe drug/sedation discrepancy, altered signed entry, missing anesthesia record), `S1 REQUIRED`, `S2 REVIEW`, `S3 STYLE`, `S4 INFO`. Overall result computes to `BLOCKED` / `NEEDS CLINICIAN ACTION` / `READY FOR CLINICIAN REVIEW` / `AUDIT PASS — CLINICIAN REVIEW STILL REQUIRED`, with an explicit rule: "Do not return a percentage or a compliance score." Orthogonal to severity is a **killer-item tag** (`KILLER_RULE_IDS`) borrowed from aviation checklist doctrine (`sources/high-stakes-documentation-patterns.md` §1) — the subset whose single omission is independently case-losing. The 2026-08-08 co-design PR made killers **hard-block** Copy/Submit with no acknowledgment escape.

**The four-state field model** (`sources/tn-des12-legal-blueprint.md`) is the data-model rule the merged PMS must adopt at schema level: *Affirmatively present / Affirmatively absent / Not applicable / Not documented — review required*, with the invariant "'Not documented' must never be silently transformed into 'none.'" `skill/references/terminology-and-style.md` expands this into three enumerations that must not be collapsed: Evidence source (clinician observed / patient reports / parent or guardian reports / external record states / test result shows / image interpretation states), Data state (Present / Absent / Not assessed / Not applicable / Unknown / Unresolved), and Procedure state (Recommended / Planned / Authorized / Consented / Started / Completed / Partly completed / Stopped / Deferred / Declined).

**The provenance model** from `sources/curve-hero-des12-blueprint.md` is field-level: `{value, status, sourceType, enteredBy, enteredByRole, confirmedBy, certainty, copiedFromEncounter, sourceTranscriptSpan}`. Its stated rationale is load-bearing for a PMS: "Curve's audit trail is activity evidence, not a version-control system, [which] is the reason provenance must travel IN the note text rather than being assumed recoverable from metadata."

**Three identities, stored separately** (`sources/tn-dental-note-standardization-curve-hero.md`): entry author (who typed it), clinical performer (who did it), responsible/reviewing dentist (who diagnosed, planned, or affirmed). "A dentist's review must be a separate event, not an overwrite of staff attribution."

**Module/composition architecture.** Notes compose as `Universal Core + one or more procedure add-ons + high-risk overlay + state/facility/practice overlay + deterministic and semantic audit + clinician comparison and EDR completion`. `skill/assets/dental-note-templates.md` ships a module router table mapping ~30 visit types to add-ons: Examination, Emergency, Imaging, Preventive, Direct Restorative, Fixed Prostho, Removable Prostho, Endodontic, Periodontal, Implant, Operative, Extraction, Biopsy/Lesion/Infection, Bone Graft/Regeneration/Sinus, Dentoalveolar Trauma, Nitrous Oxide, Sedation and Anesthesia, Pediatric and Behavior, Orthodontic, Oral Medicine, Sleep Apnea and Oral Appliance, TMJ and Orofacial Pain, Cosmetic and Whitening, Medication and Prescription, Teledentistry, Communication and Follow-Up, Pathology Result, Refusal and Incomplete Care, Late Entry/Correction/Addendum, Universal Procedure. Critically, `benchmarks/smile-notes-vs-curve-hero.md` argues the module registry must stay **developer-only and versioned**, not staff-authored, because "every practice-authored field is standardization the audit engine cannot see, which turns one standard into local dialects and makes the ruleset version meaningless."

**The AI architecture and its cage.** `docs/model-charter.md` places the product at Level 0 on a 0–7 control ladder (prompt templates, schemas, routing; no learned parameters anywhere in the repo). Two AI surfaces exist: **Byte** (always-on, deterministic advisor, no provider call) and **ByteStar/SuperByte** (optional Level-0 prompting behind `BYTESTAR_ENABLED`, with a silent killswitch `BYTESTAR_KILL`, escape-detector ladder warn→reset→perma-kill within 1h, dual PHI scan before any provider call with no override, `verifyMeaning()` on any proposed rewrite, self-consistency voting across `BYTESTAR_READS` 1–3 reads, mandatory evidence quotes, a fixed disclaimer, and a Team-Lead-visible transparent log). ByteStar is strictly one-way: staff read, staff never prompt, there is no copy path and no thumbs. `docs/bytestar-architect-audit.md` renders the full flow as a Mermaid diagram: draft → local benchmarks → deployment door → PHI gate → input escape scan → practice RAG → gateway model → output escape scan → source allow-list + verifyMeaning → strip → one-way human read → drift log.

**Dictation architecture** (`docs/voice-dictation-architecture.md`) is a four-phase ADR behind a `DictationEngine` seam: Phase 1 browser speech (shipped, `offDevice: true`, deployment off-switch `NEXT_PUBLIC_DICTATION_DISABLED=1`), Phase 1.5 read-only enrollment gate (shipped), Phase 2 on-device Whisper WASM/ONNX with self-hosted weights under `/public` (planned; blocked on a frozen dental WER eval corpus), Phase 3 cloud STT under BAA + private endpoint + zero retention (explicitly "not planned; listed so 'no' is a position with conditions"). Seven invariants hold in every phase, including "English only", "normalization is join-only — no autocorrect", "dictated text has no privileged path", and "no audio artifact, in any phase."

## Phi security observations

- The product's entire compliance posture rests on holding no PHI, and the docs say so explicitly. /home/user/catcorner22/dental/skill/references/deployment-recommendation.md lists required controls including 'no patient-identity fields', 'browser-side prohibited-data gate before transmission', 'no raw-note upload followed by attempted de-identification', and 'no note content in storage, logs, analytics, replay, traces, URLs, errors, or support tickets'. The merged PMS keeps the last one as a valuable discipline but must discard the first three.
- 2026 HIPAA Security Rule Final Rule requirements are documented but not implemented. /home/user/catcorner22/dental/knowledge/sources/tn-dental-legal-best-practices.md: the rule 'removes the addressable loophole: MFA mandatory for all ePHI access, encryption mandatory at rest and in transit, documented asset inventory, annual security risk analysis, BAAs must name specific security controls, tested incident-response plan.' The artifact §9 next-action #7 lists all of these as undecided. Tennessee breach notification is 45 days, shorter than HIPAA's 60. HIPAA penalties up to $50,000 per violation.
- MFA is off by default and gated behind a deployment flag. /home/user/catcorner22/dental/knowledge/sources/adversarial-it-hipaa-security.md rates this KILL: 'MFA_ENABLED must be "1" or login never asks for a second factor — even for accounts with stale enrollments.' /home/user/catcorner22/dental/docs/GO-LIVE.md §3 documents turning it on but warns to create a second admin first ('MFA with one Developer and one lost authenticator is a locked-out practice'). The codesign file lists 'MFA-on as ops default' as still open.
- Shared-device identity is the most-repeated kill across the entire adversarial corpus. Named as a pilot kill criterion by the IT officer (C1), the office manager (D), the temp recruiter (kill 3), the privacy attorney (angle 4), and the DSO VP. The failure is concrete: one iPad stays signed in across hygienists and rooms; the next writer inherits the prior author's draft, role, and My blocks. ALCOA+ Attributable specifically means a unique individual, never a shared account (/home/user/catcorner22/dental/knowledge/sources/high-stakes-documentation-patterns.md §6). Partial mitigations shipped 2026-08-08: Switch-author with draft wipe + sign-out, and a 10-minute shared-tablet idle lock. True per-patient re-auth mid-session remains unbuilt.
- Session lifetime is ~30 days on a JWT cookie, with revoke-all and a password-change watermark that only fire if someone presses the button. The IT panel rates this PAIN: 'Thirty days is not a chairside session.' Idle chairside tablets do not self-evict. Note the countervailing security property documented in /home/user/catcorner22/dental/knowledge/benchmarks/ux-performance-review.md: freshSessionUser() re-reads the caller's role and active state from Postgres on EVERY page load specifically so a demoted or deactivated account loses access on its next click rather than when the JWT expires — 'that is a security property worth the DB read; do not fix it by caching it.'
- The clipboard is the product's primary egress and is outside any BAA boundary. 'Copy for Curve' calls navigator.clipboard.writeText(markdown) with the full composed note; on permission failure it falls back to downloading a .md file. The IT panel: 'You do not control the sink. BAA covers your app. It does not cover whatever the clipboard manager cached after lunch.' The demand is to treat Copy as a disclosure event with an audit row, not a convenience click. The privacy attorney adds: clipboard TTL where the platform allows, and no silent unencrypted download fallback. A merged PMS that owns the chart eliminates most of this by removing the two-app hop — but any export, print, or portal-send path recreates it.
- Local draft mirrors write clinical text to the device in cleartext. /home/user/catcorner22/dental/knowledge/sources/draft-autosave-reliability.md documents an IndexedDB ring plus localStorage fallback as a deliberate reliability control ('a clinician can finish a complex note and lose power in the seconds before Submit'). The privacy attorney calls the same code an exhibit: 'Dirty drafts with names, phones, dates sit on the iPad until save succeeds. Calling it de-identified because it matches the draft is the exhibit caption.' Demands: bind backup to the authenticated user, wipe on sign-out and author switch, and offer a shared-iPad mode that disables local backup entirely. Sign-out wipe shipped 2026-08-08 (clearAllDraftBackups + SignOutButton).
- The chart-identity check is a checkbox, not a technical control. The export dialog asks the user to confirm the correct chart is open and that two identifiers matched; the product's own copy admits it 'cannot see which chart is open.' The privacy attorney calls this manufactured consent. The TN research is the origin of the two-identifier requirement: 'The interface should require the user to match at least two patient identifiers against the open Curve chart before confirming the paste.' In a merged PMS this becomes a real technical control because the PMS owns the chart — a genuine win from the merge.
- PHI gates are asymmetric between the AI path and the export path. Any phi.* finding hard-blocks the model call with no override (src/lib/assist/service.ts), while a bare name is S2 on Copy and export and only 'review' on the title-to-filename path. Dates, phones and MRNs do block. The privacy attorney's demand: 'names that gate AI must gate Copy — or admit Copy is a known PHI path and stop calling the product PII-free by premise.'
- The PHI override is a waiver, not a removal, and the docs know it. The dialog's own comment predicts the failure mode: 'between patients the waiver wins.' Mitigations already present are good and portable: masking is offered BEFORE the waiver, replacing each flagged item with a random token like [PERSON-A7K2] that is not derived from the replaced text, repeats within a note collapse to the same token so the note still reads, and tokens differ between notes 'so they cannot be joined up across records into a patient key' (/home/user/catcorner22/dental/skill/references/data-hygiene-guide.md). Override requires a written attestation of at least four real words, the attester's name and reason become part of the filed record, and the override is written to the audit log. Server-side isValidPhiAttestation enforces it.
- Autosave writes before any check completes, and the docs state the consequence honestly: 'text is saved before any check has finished, and before any human has decided anything. If a patient's name or number is typed into a draft, it exists in the database from that moment.' Remediation is editing it out so the next autosave overwrites the stored copy — with the explicit caveat that 'database backups and storage-level artifacts are outside the app's control, which is one of the reasons the rule is never type an identifier in the first place rather than the tool will clean up after one.'
- Email threading deliberately avoids a PHI token, and the reasoning is a reusable design precedent. /home/user/catcorner22/dental/skill/references/data-hygiene-guide.md: a token built from initials + birth year would be a Safe Harbor violation (dates connected to an individual, plus a unique identifying code) and is usually unique on its own in a practice this size. 'A subject line is the worst place to carry it: subject lines travel between mail servers in the clear, are copied verbatim into bounce messages and out-of-office replies, are indexed by mail search, and appear in phone notification previews on a locked screen.' It also rejects the white-text workaround: 'invisible-but-present data is still fully present... while the people who might have noticed the mistake are the only ones who cannot see it.' The token is the ticket and nothing else.
- Third-party surface is deliberately minimal and each addition is a documented BAA decision. CSP connect-src 'self' means zero third-party scripts, fonts, or analytics; every image is a hand-authored local SVG. Three optional providers exist, each flagged: Resend for email ('Resend therefore processes clinical content: get a BAA in place before real patient records flow'), the AI gateway ('Note text goes to the configured provider after the PHI gate. Get a BAA in place first'), and the browser speech engine (offDevice: true, labeled in UI, with a deployment off-switch). GO-LIVE.md §5 flags a dangerous asymmetry: 'SuperByte turns on from AI_GATEWAY_API_KEY alone, without ASSIST_ENABLED' — so adding a key to try assist silently enables a second feature that sends draft text to the provider.
- Production database safety is enforced in code, not documentation. resolveDbBackend rejects production without POSTGRES_URL and refuses every value of PGLITE_DIR including memory://, with the failure mode spelled out: 'an in-memory database looks completely healthy — logins work, notes save, history renders — right up until the instance recycles and every clinical record is gone.' Preview deployments must not inherit POSTGRES_URL: 'A Preview deployment inheriting it would write real clinical rows from an unreviewed branch.'
- Audit logging exists and logs named actions with codes and versions but never note content or prompt bodies. bytestar.drift / bytestar.escape / bytestar.refused rows carry 'codes/versions/tokens only'. An (action, at) index was added for scale. Two gaps the corpus names: no clipboard/export disclosure rows, and no plain-sentence rendering of the audit trail. The latter is an EU GMP Annex 11 requirement the research recommends adopting — the trail must be 'convertible to a generally intelligible form' for a non-specialist reviewer, e.g. 'Sarah Philips replaced the extraction outcome in ticket T-1043 at 4:12pm ET, reason: corrected tooth number' — and Annex 11 also requires the trail be regularly reviewed as a documented act, which the corpus proposes as a monthly Team Lead review that writes its own audit row.
- Attorney-client privilege does not shield the clinical record from a Board investigation, and the corpus says so bluntly. /home/user/catcorner22/dental/knowledge/sources/tn-board-investigator-hate.md finding 4: 'Patient notes, charts, frozen submissions, ruleset versions, and who attested what when are practice records and Board evidence, not a conversation with counsel... If the software raised completeness killers and staff attested past them or Copied anyway, that trail is consciousness + override, not a privilege cloak. Telling the Board "Smile Notes said we were fine" is a false exculpation.' Practice policy must say this in one page.
- Multi-site Minimum Necessary is absent. Offices exist as labels, every office is selectable by everyone, and there is a single database tenant. For a PHI-holding product this fails the Minimum Necessary standard, cross-office access review, and litigation-hold isolation. The DSO panel's E5 states the requirement: 'Office/region as authorization, not picker order... Cross-office browse is a deliberate grant, not the default.'
- Rule 0460-01-.12 lists unauthorized disclosure of identifiable facts AND false, materially incorrect, or inconsistent patient-record entries as unprofessional conduct in Tennessee — so record integrity and privacy are both licensure exposure, not only federal exposure. /home/user/catcorner22/dental/skill/references/tennessee-dental-law-summary.md.
- The de-identification screen cannot certify anything and the skill says so in its safety boundary: 'Do not state that text is de-identified merely because obvious names are absent. Say that only the practice can complete its HIPAA de-identification review.' The source ledger repeats it: 'The Skill cannot certify HIPAA de-identification, documentation completeness, code correctness, standard of care, or billing compliance.'
- No formal Security Risk Analysis has been performed. The IT panel is explicit that it is 'not a formal Security Risk Analysis', and the artifact lists the annual SRA as an undecided operational control. The 2026 rule makes it mandatory rather than addressable.

## Product insights

- CURVE HERO BENCHMARK — the persistent context panel is the single most-copied idea. Curve's Sidekick stays visible across every module and gives 1-2 click access to Charting, Notes, Perio, Imaging, Billing, Files & Letters and Profile from one patient selection, with expandable summary sections (Appointments, Insurance, Recare, Profile, Billing/aging, Notes) and hover flags for medical conditions, forms and insurance. PMS requirement: a persistent patient rail is the primary navigation object, not a page. It must also carry a privacy mode that hides names — Curve has one, and a PHI-holding PMS in an open operatory needs it more. Source: /home/user/catcorner22/dental/knowledge/sources/curve-hero-pms-clinical-documentation.md.
- CURVE BENCHMARK — Critical-note alerting is Curve's strongest visual pattern and should be adopted wholesale but generalized. The Notes module icon turns red whenever a Critical-tagged note exists; critical notes are always visible in Sidekick and carry a red icon when expanded. PMS requirement: a single practice-wide 'must not miss' channel (allergies, premedication, anticoagulation, latex, behavioral, guardianship, financial hold) that is impossible to collapse away and that surfaces on patient selection, not on module entry.
- CURVE BENCHMARK — note tags control BEHAVIOR, not labels, and this is the mechanism to copy. Curve's ~24 system tags govern attachment, visibility, and behavior: Treatment Planning (default pre-checkout note on visits), Clinical History (visit/DOS-attached, preferred for continuity), Clinical (standalone), Critical (always visible + red alert), plus Perio, Image, Chart Label, Pop-up (appears on patient selection), Billing, Correspondence, Memo/To Do. PMS requirement: model note type as a behavior contract with declared attachment, visibility, and alerting semantics — never as a free-text category.
- CURVE BENCHMARK — the highest-value correctness finding in the whole corpus: context-of-creation determines attachment, and the tag does not. 'A note tagged Clinical History from Sidekick or the Notes module is NOT attached to the visit; only a note created from the Visit or from Charting History attaches to the date of service.' PMS requirement: attachment must be a structural property of the note record (a required foreign key to visit/encounter), never a user-selected label that can silently be wrong. This one design decision eliminates an entire class of orphaned-note and wrong-visit errors that Curve users live with. Source: /home/user/catcorner22/dental/knowledge/sources/curve-hero-des12-blueprint.md.
- CURVE BENCHMARK — checkout auto-conversion is a documented liability trap to redesign, not copy. Curve auto-converts Treatment Planning notes to Clinical History and attaches them to the date of service at checkout, while charted procedures simultaneously move from Planning to History. 'Recycled template language becomes the legal DOS note if nobody individualized it.' PMS requirement: keep the workflow convenience but gate the conversion — a plan-authored note may not become the legal encounter note until a human has individualized it and the completeness gate passes for the procedures actually performed.
- CURVE BENCHMARK — shortcut-driven charting is the real speed advantage and must be matched. Customizable Shortcut buttons including multi-tooth/multi-code macros are the fastest path; procedures 'paint' onto the odontogram via click or click-and-drag surface selection and auto-populate the Treatment Plan Card with ADA/CDT code, description, site, surfaces, material, and visit grouping. Curve claims 3.5x faster charting (unverified marketing). PMS requirement: charting is a painting gesture with macro shortcuts, and every painted procedure must propagate structured facts (code, site, surfaces, material, provider, visit group) into the plan and the note simultaneously — one gesture, many derived records.
- CURVE BENCHMARK — Treatment Plan Cards with per-visit sequencing and money are a case-acceptance instrument. Cards organize procedures into visits with insurance/patient/total estimates and PPO write-offs; they expand, resize, separate, and reorder; multiple independent plans/tabs per patient support phasing and options. Curve claims ~30% case-acceptance improvement from patient-friendly visuals (unverified). PMS requirement: multiple concurrent plans with visit phasing and per-visit patient-portion estimates, presentable to the patient. Note the direct tension with the practice's own instruction in the dental repo: money stays out of the clinical record entirely. Resolve as separation of surfaces, not suppression of data — plan and ledger hold money; the clinical note does not.

- PRACTICE-CONTENT GOVERNANCE — the central tension the merged PMS must resolve deliberately. Forbidden in v1: new freeform clinical paragraphs, new audit fields, auto-insert on tap. - CHAIRSIDE UX LAW — 'Home is the note.' The design-tokens doc states it as a rule: 'Fast Lane does not restore the old dashboard card grid as the front door. - CHAIRSIDE UX LAW — the surprise finding from the friendly panels reframes the whole gate design: 'they don't hate gates — they hate reading under time pressure. Fewer words + bigger targets at the gate.' PMS requirement: every blocking message is one verb line plus one control; explanations live in progressive disclosure; policy prose never appears on the finish path.
- VALIDATION TIMING — live validation while a clinician is mid-sentence is classified as a hostile pattern. 'Anywhere audit findings appear while the clinician is still typing a sentence, NN/g's category for that is hostile: it reads as grading a test before the student has answered. Rule: silent until blur (or until a sentence boundary), live only after a field's first error.' PMS requirement: state the validation-timing policy explicitly and test it — the corpus notes this is 'the quiet adoption killer.'
- OMISSION LICENCES — the documented answer to 'rigid protocols are too slow', borrowed from emergency medical dispatch. A required field may be satisfied by an explicit, recorded, NAMED licence ('not applicable — obvious from procedure', 'already stated in another section'), and the audit records WHICH licence was used. 'That is different from an override: the licence is finite, named, and countable.' GOV.UK supplies the complementary rule: if 'I do not know' is a valid state it must be a first-class answer, because 'an explicitly-chosen "not documented at this visit" is defensible in a record; a blank is not, and forcing a value is how fabrications enter notes.' PMS requirement: build named omission licences on every required field; this is simultaneously the main adoption unlock and the main defense against invented content.
- INDEPENDENT VERIFICATION — the design is specified and unbuilt, and it is the corpus's highest-rated liability control. DOE distinguishes three second-person tools that are deliberately not interchangeable: peer-check (same time and place, informal, requested by the performer), concurrent verification (two people separately confirm at the same time and place), and INDEPENDENT verification (separated by time AND distance from the person who created the condition — the separation IS the mechanism). For software: the second person sees the CLAIM and the note, never the first person's reasoning, and cannot be the same account. Scope it narrowly to PHI override, killer-item attestation, and rule-disagreement escalation. 'One queue, one status, one audit-log action.' Both the carrier and the Lead panel demand it; the owner panel votes PARK until after pilot numbers. PMS requirement: build it as a bounded feature and let policy decide the scope.
- READBACK — the strongest single UX idea in the cross-domain research, still unbuilt. ICAO's insight is that readback is SCOPED: not every token is read back, only a named safety-critical class. Define a READBACK_CLASS — tooth numbers, surfaces, quadrants, drug names, doses and units, anesthetic carpules, times, laterality — and on accepting any AI rewrite or any bulk transformation, make the clinician confirm THOSE TOKENS ONLY as a short list rather than a paragraph. 'It converts diff review from a wall of text into five items a human can actually check.' PMS requirement: apply this to every high-stakes transformation, including imported data during a PMS conversion.
- REASON CODES — two independent domains land on the same requirement, which the corpus calls a strong signal. Legal-ops exception routing and EU GMP Annex 11 §9 both require a reason for change captured as a short predefined list PLUS optional free text, because 'a reason captured as a short predefined list plus optional free text is reviewable in aggregate, where pure prose is not.' PMS requirement: controlled reason codes on every attestation, override, late entry, amendment, and local-vocabulary change — and then actually aggregate them, which the Lead panel says is the step currently missing ('you collected the data and buried it').
- ATTESTATION AUTHORITY TIERS — currently absent and demanded by three panels. The legal-ops convention is that authority is pre-assigned per severity: an assistant may attest S2/S3, a clinician S1, and the killer-item class plus any PHI override needs a second named person. Today 'any user can attest anything' and 'staff attest everything so the Andon goes green.' PMS requirement: bind attestation authority to clinical role and severity class, and surface a practice-level attest-code mix so 'correct-as-written' spam reads as a template problem before it reads as a person problem.
- VERBATIM-LOCKED BLOCKS — borrowed from emergency dispatch's scripted Pre-Arrival Instructions. Only the highest-stakes text is verbatim-locked: consent language, post-op instruction sets, complication statements become verbatim:true blocks that cannot be edited at all — only accepted, rejected, or placeholder-filled — while everything else is editable prose. 'Today the residue rule enforces placeholder replacement but not verbatim integrity.' PMS requirement: mark the legally-sensitive block set as verbatim and enforce it.
- PROCEDURE USE LEVELS — declare per module how closely it must be followed, and treat an unfollowable module as a defect. DOE requires the required closeness of adherence to be DECLARED per procedure, and puts the obligation on the procedure: 'procedures must be capable of performance as written; if not, stop and fix.' Some modules should be continuous-use (extraction, medication, sedation), others reference-use. 'A module that cannot be filled truthfully for a real visit is a bug in the module, and the wish channel is the stop-and-fix path.' PMS requirement: declare use levels, and route 'this module cannot be completed truthfully' as a first-class defect report, not user error. The documented answer to why operators follow procedures is three things: the procedure is correct and executable as written, there is a real low-friction non-punishing channel to change it, and the required closeness of adherence is declared.
- MEDICATION SAFETY — the abbreviation and dose rules are non-negotiable and already curated. The Joint Commission Do-Not-Use list reproduced in full: U/u -> unit; IU -> International Unit; Q.D./QD -> daily; Q.O.D./QOD -> every other day; trailing zero (X.0 mg) -> X mg; LACK of leading zero (.X mg) -> 0.X mg; MS/MSO4/MgSO4 -> write the full drug name. The kilogram rule: the most common weight-based dosing error is pounds treated as kilograms, a 2.2x overdose. Household spoons vary ~2x in delivered volume; mL plus an oral syringe is the standard. Including the mg/kg basis on the prescription enables independent double-checking. The critical design rule: a Never-use abbreviation must be FLAGGED and never expanded, because 'expanding one of these would launder it: the note comes out clean, the reader is reassured, and the writing habit that caused the documented error survives completely intact.' PMS requirement: build the three-category vocabulary model (Expand / Ask / Never use) into the charting layer and the e-prescribing layer.
- MEDICATION SAFETY — a curated dental drug-interaction short list exists and is flag-only. - PATIENT-FACING LANGUAGE — the Cures Act makes plain, person-first, non-stigmatizing wording a documentation requirement rather than a courtesy, and the corpus supplies two opposing dictionaries. The clinical record wants 'radiograph'; the patient summary wants 'x-ray' — and the audit applies each list only where it belongs. ~50 plain-word pairs are curated (caries -> tooth decay or a cavity; periodontitis -> gum disease that has reached the bone; necrotic -> the nerve inside the tooth has died; edentulous -> no natural teeth left in that area). PMS requirement: a real portal needs both dictionaries, a portal-delivery gate, and a standardize pass that is disabled or inverted on patient-audience fields.
- BOUNDED NEGATIVES — a precise taxonomy the note UI should enforce structurally. Patient-reported ('Patient denies fever or facial swelling today' = what the patient said); clinician-observed ('No facial swelling observed on today's examination' = scope of observation); procedure-bounded ('No immediate complication observed before discharge' = limited period); and overbroad absolute ('Patient had no complications' / 'No problems' = avoid, implies knowledge beyond the encounter). PMS requirement: make the bounded forms the one-tap options and the absolute form unavailable, rather than flagging it after the fact.
- SUBJECTIVE ATTRIBUTION — a small rule with large litigation value. 'Patient reports pain for three days' is preferred over 'Tooth has been painful for three days' — the transformer must not promote a patient statement to an established fact. Combined with the evidence-source enumeration, PMS requirement: every narrative fact carries its source type in the data model, and the rendered note preserves the attribution in prose.
- STRUCTURED-BEATS-FREE-TEXT CONFLICT RULE — 'Free text is the least authoritative input. PMS requirement: in a PMS where the odontogram, the perio chart, the med list, and the note all describe the same visit, cross-surface contradictions must be a blocking finding, not a silent precedence rule. The corpus's own high-risk check list already enumerates the comparisons (planned vs consented vs performed; consent vs care actually performed; diagnosis/indication/procedure/image/prescription/billing site; no-allergy vs named allergy; no-anesthetic vs recorded anesthetic; no-complication vs adverse event/rescue/reversal; intended vs achieved sedation depth; narrative vs time-oriented anesthesia record).
- AUTOSAVE AND RECOVERY — treat unsaved keystrokes as a patient-outcome risk. 'Smile Notes files what the SERVER holds at submit time — so unsaved local keystrokes are a patient-outcome risk, not a convenience gap.' The stack: debounced server PATCH (~0.5-1.5s) with optimistic concurrency on a base version; flush on pagehide/visibilitychange with keepalive fetch; retry on online with soft backoff, never a hammer loop; a same-device durable mirror for the window before server ACK; and a capped server revision ring for 'restore a few minutes ago' as working-copy recovery, not legal history. The merged PMS must decide this deliberately.
- NO-SCOREBOARD DOCTRINE — quoted from the product's own source, and independently demanded by the RDH, Lead, faculty, DSO and owner lenses: 'a running tally is how a quality tool becomes a performance-management tool, and staff who believe they are being scored write the shortest note that clears the gates — which is the exact outcome this product exists to prevent.' This is a hard commercial constraint, not a preference: two panels name it as a walkout trigger.
- AI CLAIMS DISCIPLINE — a naming rule with commercial consequences. The charter's honest label is 'a bespoke AI SYSTEM with a deterministic core and an optional, verifier-gated Level 0 assist. It is not a bespoke LLM, and calling it one would be the category error the guide opens with.' Combined with the owner panel's ban on lawsuit-prevention language and the carrier's list of theater it will not pay for, PMS requirement: marketing may claim reproducibility against a stamped ruleset version, deterministic gates, and gap reduction under a time guardrail — never 'AI-powered,' 'lawsuit-proof,' 'board-proof,' 'HIPAA compliant' as a product property, or any indemnity ROI.
- COMPLIANCE DOSE-RESPONSE — the most persuasive number in the corpus for a buyer conversation, with its caveat attached. IAED reports the correct determinant level was chosen 36.5% of the time when neither Case Entry nor Key Questions hit 100% protocol compliance, 74.5%/82.2% when one did, and 93.2% when both did. The argument it supports: partial protocol compliance is not partial safety. The caveat the corpus attaches: 'self-published by the standards body; the primary study was not read. PMS requirement: score whether each required element was addressed AT ALL, separately from whether the note was good — and use risk-scaled review sampling (100% review while a staff member is new or after a rule change, decaying to a percentage) so human review stays sustainable.
