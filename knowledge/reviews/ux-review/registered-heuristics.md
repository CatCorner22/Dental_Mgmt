# Registered heuristics for the UI and UX review

Registered 2026-09-12 before the audit ran; the compact form of this table is in `docs/16-ux-review.md` under "Registered heuristics", and the machine-readable form is `registered-heuristics.json` beside this file. Nothing here changes after registration; the audit scores the prototype against these rows and against no others.

How the rows were made: seven research agents each turned one body of research into testable heuristics, fetching primary sources from GitHub (the W3C `w3c/wcag` repository, `dequelabs/axe-core`, `nhsuk/nhsuk-frontend`, `alphagov/govuk-frontend`, `uswds/uswds`, `w3c/wai-tutorials`, `alphagov/govuk-design-system`, `nhsuk/nhsuk-service-manual`, Ant Design, Shopify Polaris and `Myndex/SAPC-APCA`) because the environment's network policy blocks the standards bodies' and design systems' own websites. Three independent critics then re-fetched every one of the 152 quotes the authors marked verified, with a normalised verbatim match (tags stripped, whitespace collapsed, case and quote marks ignored, at most one word of difference), and struck none; a spot check by the reviewer re-fetched four more at random and found all four. A fourth agent found 33 groups of duplicates across the seven bodies and dropped 52 rows, keeping in each group the row with the fetched source and the more precise test; where kept rows overlap it recorded the tension rather than merging them (`research/dupes.json` in the review's working set, summarised in docs/16).

Evidence labels: **fetched primary source** (a standards body's text or a design system's own source file, fetched this session, quote found verbatim); **fetched secondary source** (a design system's or vendor's reading of the research, same test); **training knowledge, unverified** (no primary source could be fetched; the row is a claim to check, not a fact established here).

### WCAG 2.2 Level AA (with the cheap, relevant AAA criteria 1.4.6 Contrast Enhanced, 2.5.5 Target Size Enhanced, 2.4.13 Focus Appearance and 2.4.12 Focus Not Obscured Enhanced noted as should-level)

21 heuristics, 21 verified against a fetched source. Gaps the researcher declared: All quotes come from the w3c/wcag GitHub source files (raw.githubusercontent.com), which is the editors’ draft tree, not the published w3.org/TR/WCAG22 Recommendation; the normative sentences quoted are the same in the June 2023 Recommendation to the author’s knowledge but that equivalence was not verified because www.w3.org is blocked. The source HTML carries inline <a> glossary links inside sentences, so quotes were cut to tag-free fragments and verified after tag-stripping and whitespace normalisation; a critic viewing the raw file will find them contiguous. Focus Appearance 2.4.13 was confirmed to be Level AAA in WCAG 2.2 (conformance-level tag in the fetched file), so it is scored should, not must. The Understanding documents for 1.4.3, 1.4.11, 2.4.11, 2.4.13, 2.5.8, 3.3.4, 4.1.3, 3.2.6, 3.3.7 and 2.5.7 were fetched and read; only passages that were tag-free and under 40 words were quoted. Not turned into heuristics to stay within 25: 2.4.1 Bypass Blocks (the .skip link exists; test trivially), 2.4.3 Focus Order and dialog focus return (ui.js implements it; belongs to an interaction body), 2.4.6 Headings and Labels, 4.1.2 Name Role Value, 1.3.4 Orientation (tablets rotate; worth a portrait/landscape probe), 2.5.2 Pointer Cancellation (gloved down-event misfires), 1.4.13 Content on Hover or Focus, 1.3.5 Identify Input Purpose (autocomplete tokens on patient fields), 3.3.8 Accessible Authentication (the PIN sign-in is a cognitive function test; it passes only if a password-manager or alternative exists) — each was fetched and could be added. The WCAG text gives no numbers for consistent navigation, consistent identification, error suggestion or status-message length, so those thresholds (0 inversions, one label per function, <= 12-word verb line) are audit conventions drawn from the prototype’s own one-verb-line rule, not from WCAG. Large-text size (18pt/14pt bold, i.e. 24px/18.66px) comes from the fetched glossary term large-scale; the px conversion is the auditor’s. Contrast ratios cited in tests were computed from tokens.css hex values with the WCAG relative-luminance formula and should be re-run against rendered pixels, since composited overlays and the grayscale filter change them.

### What automated accessibility testing (axe-core 4.13.0 as vendored in scripts/vendor/axe-core and run by scripts/a11y-check.mjs) can and cannot prove for this prototype: which WCAG 2.x A/AA criteria have an axe rule, which have none and need a scripted Playwright check, and how 'incomplete' (needs-review) results must be handled so they are never counted as passes.

13 heuristics, 13 verified against a fetched source. Gaps the researcher declared: Nothing on w3.org, deque.com, webaim.org or MDN was fetched; all WCAG quotes come from the normative SC fragments in the w3c/wcag GitHub repo (raw HTML with inline <a> tags, so quotes were chosen as tag-free spans), and no Understanding documents were consulted, so the definitions of 'target', 'status message', 'process' and 'essential' rest on the normative text alone. The axe evidence is the develop branch rule JSON and docs, not a 4.13.0-tagged snapshot; the vendored build was checked empirically instead (version string 4.13.0, target-size enabled:false yet run under the wcag22aa tag). Coverage mapping: axe's default tag run touches 1.1.1, 1.3.1 (structure/tables), 1.3.5 (autocomplete-valid, inapplicable here), 1.4.1 (links only), 1.4.3, 1.4.4 (viewport only), 1.4.12 (inline styles only), 2.1.1/2.1.3 (scrollable regions only), 2.4.1 (needs-review only), 2.4.2, 2.4.4, 2.5.8 (target-size), 3.1.1/3.1.2, 3.3.2 (multiple labels only), 4.1.2; it has no rule at all for 1.3.2, 1.4.10, 1.4.11, 1.4.13, 2.1.1 operability, 2.4.3, 2.4.7, 2.4.11, 2.5.2, 2.5.7, 3.2.2-3.2.6, 3.3.1, 3.3.3, 3.3.4, 3.3.7, 3.3.8 or 4.1.3 - those are the scripted heuristics above. Not turned into heuristics: 3.3.8 Accessible Authentication (the PIN step-up is a cognitive function test; whether a 6-digit PIN on a shared operatory tablet needs an alternative is a policy question the audit should raise, not a Playwright check), 1.3.4 Orientation, 1.4.13 hover content (no tooltips found) and 2.5.2 pointer cancellation (ui.js binds click, not mousedown, except the dialog mousedown focus guard - a one-line check).
